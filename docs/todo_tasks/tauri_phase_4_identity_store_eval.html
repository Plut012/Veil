Acceptance Criteria

✓
IdentityStore::new() creates dirs with 0o700 permissions. Both {veil_dir}/ and {veil_dir}/keyring/ are created with fs::create_dir_all and then fs::set_permissions(0o700) on Unix. Verified by test_directory_permissions_are_0700.
✓
Passphrase derived to storage key via Argon2id. Argon2::default() (Argon2id variant with default memory/iteration parameters) is called via hash_password_into(passphrase, salt, &mut key). The 32-byte output key is used for all subsequent encrypt/decrypt operations.
✓
Salt generated on first run, persisted at {veil_dir}/salt. On first call, a 16-byte random salt is generated via sodiumoxide::randombytes::randombytes(16) and written to salt. Subsequent calls read the file. Verified implicitly by the persistence test: two store instances opened with the same passphrase produce the same storage key and can decrypt each other's contacts.
✓
Contacts encrypted as individual .enc files. Each contact is stored at keyring/{contact_id}.enc as encrypt(serde_json::to_vec(&contact), &storage_key) — XSalsa20-Poly1305 sealed bytes. Verified by test_contact_files_are_encrypted.
✓
Contacts survive close/reopen with same passphrase. A contact added in one store instance is present after creating a new instance with the same passphrase pointing to the same directory. Verified by test_persistence_across_instances.
✓
Wrong passphrase results in empty contact list (no crash). load_contacts() silently skips files where decrypt() returns an error. A store opened with the wrong passphrase returns an empty list_contacts(). Verified by test_wrong_passphrase_yields_empty_list.
✓
CRUD operations: add, remove, get by ID, get by channel, list, update. All six public methods implemented with correct memory + disk semantics. Each has a dedicated test.
✓
Contact files on disk are not readable as plaintext. serde_json::from_slice on the raw .enc file returns an error. Verified by test_contact_files_are_encrypted.
✓
cargo test passes all identity tests. 10 new identity tests (2 contact, 8 store) added to the suite. All 42 total tests pass.

Implementation Notes

  • No unwrap() in library code. All public and private functions return Result and propagate errors with ?. The only .expect() calls are in test helpers (sodiumoxide::init()) and in the crypto engine (a pre-existing invariant asserting a 32-byte slice is always valid for secretbox::Key::from_slice).
  • Salt generation uses sodiumoxide::randombytes::randombytes(16). Sodiumoxide was already a project dependency and initialized; this avoids pulling in another RNG crate just for salt generation. The salt is 16 bytes, satisfying the argon2 crate's minimum of 8 bytes.
  • Each test uses a unique temporary directory. std::env::temp_dir().join(Uuid::new_v4()) ensures tests are fully isolated — no shared state, no teardown needed.
  • load_contacts() is fully silent on failure. Each step (read_dir, read file, decrypt, deserialize) is individually guarded with .flatten() or match/continue, so a corrupt or wrongly-keyed file does not prevent other contacts from loading.
  • pub mod pairing; placeholder added. An empty pairing.rs is declared in mod.rs so Phase 6 can fill it in without modifying module declarations.
  • No dirs version conflict. The plan lists dirs = "5" but the crate resolved to dirs v5.0.1. The dirs::home_dir() API is identical across both the dirs v5 and dirs v6 versions present in the dependency tree (tauri pulls in v6 internally; our code uses v5 directly).
