Component Overview

Component Veil Identity Store
Purpose Manages contacts and their encryption keys. Persists contacts encrypted on disk under a passphrase-derived key. Owns the ~/.veil/ directory structure.
Key Derivation Argon2id via nacl.pwhash.argon2id.kdf with OPSLIMIT_MODERATE and MEMLIMIT_MODERATE. 16-byte random salt stored at {veil_dir}/salt.
Storage Format One .enc file per contact in {veil_dir}/keyring/. Contents: encrypt(contact_json, storage_key) using the Phase 1 crypto engine (XSalsa20-Poly1305).

Files Created

File Description
src/veil/identity/contact.py Contact dataclass with fields: contact_id (UUID string), display_name, key (32-byte symmetric key, never written to disk in plaintext), telegram_channel_id, telegram_user_id, created_at (datetime, defaults to UTC now), envelope_template (str, defaults to empty).
src/veil/identity/store.py IdentityStore class. On init: creates directories with 0o700, derives storage key via Argon2id (generating or reading salt), loads existing contacts from disk. Public API: add_contact, remove_contact, get_contact, get_contact_by_channel, list_contacts, update_contact. Wrong-passphrase decryption failures are caught silently — store opens empty rather than crashing.
src/veil/identity/__init__.py Re-exports Contact and IdentityStore.
tests/test_identity.py 9 tests in TestIdentityStore. Covers: add/retrieve, persistence across instances, wrong passphrase, channel lookup, remove, list, update, directory permissions, and encrypted-on-disk verification. All use tmp_path — no writes to ~/.veil/.
