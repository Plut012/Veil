Component Purpose

The envelope module wraps ciphertext in user-configurable templates before sending to a messaging platform, and extracts ciphertext from incoming messages by matching against known templates. This gives encrypted messages visual personality without affecting the crypto layer — the envelope is purely cosmetic framing for the ciphertext.

The module is a clean boundary: it knows nothing about Telegram, keys, or the UI. It takes a base64 string in and returns a formatted string out, or the reverse.

Implementation Notes

  • No external dependencies — only the Python standard library re module.
  • Template substitution uses plain str.replace; no Jinja or special syntax needed.
  • build_pattern escapes all template characters via re.escape before splicing in the base64 capture group, so templates with regex-significant characters (brackets, dots, pipes) work correctly.
  • Base64 character class [A-Za-z0-9_\-=+/] covers both standard and URL-safe base64 variants, ensuring real ciphertext from PyNaCl roundtrips cleanly.
  • Empty-template unwrap uses an anchored pattern (^...$) to avoid false positives on messages that contain incidental base64-looking substrings alongside other text.
  • The tests/ directory was created as part of this phase (it did not previously exist). An __init__.py was added alongside the test file.
