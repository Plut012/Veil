Key Design Decisions

  • connection.ts simplified: Tauri IPC is always available — replaced the full reconnect-state-machine with a constant readable('connected'). The isConnected derived store always returns true, keeping existing component logic working without changes to their disabled states.
  • Passthrough mode: On initiate_pairing, bridge.passthrough is set to true so the listener task receives messages from channels not yet in monitored_channels. It is cleared after handshake detection.
  • Dual-template unwrap: Incoming messages are tried against the contact's stored envelope template and the empty template (""), so raw ciphertext is also accepted as a fallback.
  • Initiator role contact telegram_user_id: Set to 0 since the initiator does not learn the joiner's user ID from the handshake message. Only the channel ID is known.
  • Passphrase via rpassword: Uses read_password_from_tty (rpassword 5 API) so the passphrase does not echo to the terminal during startup.
  • Block-on bridge connect in setup: tauri::async_runtime::block_on is used to perform the async bridge connect synchronously before the UI opens. This allows interactive Telegram sign-in (phone + code + optional 2FA) via stdin before the window appears.
