Implementation Notes

  • No unwrap() in library code. Both Regex::new() calls use .expect() with a descriptive message instead. The hardcoded empty-template pattern is guaranteed valid; the generated pattern is valid because regex::escape() sanitizes all user input before joining with the literal capture group string.
  • regex::escape() applied to template parts only. The placeholder {ciphertext} is used as a split point, never passed to the regex engine. This is the correct approach — template literal text could contain any regex metacharacter.
  • Empty template anchored pattern. ^([A-Za-z0-9_\-=+/]+)$ ensures the entire message is a valid base64 payload with no surrounding text, preventing false positives.
  • Base64 character class. The capture group [A-Za-z0-9_\-=+/]+ covers standard base64 (+/=) and URL-safe base64 (-_), matching the output of the crypto engine regardless of encoding variant chosen in Phase 2.
  • regex crate was already in Cargo.toml from Phase 1 dependency declarations. No Cargo.toml changes were needed.
